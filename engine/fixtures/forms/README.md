# Form-code-generated engine inputs (Refs #53)

Generated by `scripts/generate-form-fixtures.ts` through the reusable form serializer/validator in `app/lib/intake-form.ts`, checked against `shared/form.ts`. The source submissions are typed form-state records in `scripts/form-fixture-cases.ts`; none of these JSON files is hand-authored. No engine code or calculator is imported by the producer. This is the new pre-integration I3/I6 form export path, not a claim that the still-open I4 screen already collects every numeric field.

Source case specification: [PR #123 INPUT-TEST-CASES.md at 82723b2](https://github.com/EdwinZhanCN/ValueIQ/blob/82723b23e23f9f088cc845b2ccc2c719b85abc70/docs/research/samples/INPUT-TEST-CASES.md), plus `docs/research/plans/01a-input-structure.md` on develop at 674723a. Form shape was cross-checked with `engine/types.ts` on the engine-core branch; this PR does not merge that engine.

## Reproduce (Node 24)

```sh
node --experimental-strip-types scripts/generate-form-fixtures.ts
node --experimental-strip-types scripts/generate-form-fixtures.ts --check
node --experimental-strip-types --test scripts/form-fixtures.test.ts
pnpm check
pnpm test:smoke
```

The generator validates and round-trips the two accepted forms through the same parser. Every negative candidate must throw `FormValidationError` with exactly one expected field/error; the generator captures that error's exact rejected candidate and formats JSON whitespace only. An invalid file is deliberately NOT a successfully validated form. Tests also prove rejected edits preserve the previous accepted form object.

`validation.json` is the handoff manifest: expected acceptance/rejection and field errors, the fixed recency reference date, and a synthetic ownership registry. Engine consumers should enumerate `*.form.json`, not the manifest. Use `2026-11-05T12:00:00.000Z` as run time for reproducible recency checks. No system clock is used to generate evidence.

## Minimum set

- `sample-result`: exact supplied three-goal values; documented effect inputs; each backing set matches the six requested flags. `cost_nature = cash` and `cost_sources = ["expedite"]` classify data quality without inventing hard cash for time savings.
- `sample-gap-list`: typed estimate, no file, recent only. Acceptance here means a valid form; confidence release/gap classification is exclusively the engine's job.
- The eleven requested invalid cases, plus `invalid-horizon-21`. Each is a separate single-defect submission. For horizon zero/21, adoption array length equals the invalid horizon so adoption-length is not an unrelated second defect. Task-time invalidation uses the task-time path instead of also supplying direct hours.

Unspecified negative values use the smallest clear counterexamples: cost -1, before 30/after 40 minutes, unknown ID `not_in_field_spec`. No supplied test value is clamped or changed. Known/cost/context are roles, not evidence tiers; known/context records use documented tier and user origin, quoted costs documented, estimated training estimate. Recapture and discount rate use benchmark/default exactly as requested.

## Integration mismatches and limits

1. Develop had no numerical form serializer/validator or shared FormFile; this PR adds them rather than passing fixtures through a fake fixture-only encoder. The intake UI in #122 still cannot enter all numerical/evidence fields. UI wiring remains I4/I6; these files are produced from typed form state, not automated screen entry.
2. `cost_nature` and array-valued `cost_sources` exceed develop's old `number | string | null` Input example. PR #123 explicitly requires them; PR #128 updates that spec. The shared type supports arrays and `vendor_supplied` metadata without rewriting or omitting those fields. Record this dependency during owner review.
3. The engine currently reads adoption from `inputs[]` and uses `version`; the earlier #127 envelope proposal used top-level adoption/`contract_version`. These fixtures use the engine wire shape, not a silent adapter. Discount-rate provenance lives on an input record matching the root setting; conflicting setting copies are rejected.
4. File IDs are synthetic references, as the case specification permits. Same-project validation uses trusted external ownership context, not a self-asserted description. Before storage integration, server callers must obtain this context from authorized file rows. No R2 upload, identity, state or access-control implementation changes here.
5. The input validator does not run arithmetic or enforce confidence floors. A valid estimate is retained for the engine to turn into a gap list. Expected output snapshots remain owned by #123; exact headline matching is not asserted by form validation.
6. Engine and form catalogs are independently implemented so this boundary test can detect disagreements. The form follows the stricter field-spec integer task counts and strict time/day improvement; any engine difference must be reviewed, not normalized away.

The second wave is intentionally not generated in this first handoff. No API keys or real files/projects are included.

## Verification

- `pnpm check` passes, including all 19 form tests and the deterministic generation check. `pnpm test:smoke` passes on port 5191 with ignored local-only auth configuration.
- The generated fixtures were also passed to the independent engine validator from engine-core commit `84cee429067151981370a6d40a192d6caabacbe5` in a temporary directory: both positives accepted; all 12 negatives rejected on the expected field. A separate TypeScript assignment check confirms this `FormFile` is assignable to that engine's `FormFile`. That engine code is not bundled into this PR.
- These are input-boundary checks, not an assertion that computed output equals #123's expected result snapshots. The engine owner performs that numerical comparison.
- `.prettierignore` excludes `CLAUDE.md`, a Git symlink to `AGENTS.md` that Windows can materialize as a text pointer. The link target is preserved byte-for-byte instead of formatting it as Markdown.
