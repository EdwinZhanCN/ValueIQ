# Decision: Tailwind v4, shadcn/ui on Base UI, and beUI for motion

Status: implemented.

## Problem

The scaffold had unstyled forms and no design system: no utility CSS, no path alias, no component primitives, and no visual identity for the landing page or future assessment UI. The interface also had to stay honest about unfinished behavior while still reading as a credible product surface.

## Decision

- Style with Tailwind CSS v4 and a small semantic token layer: one neutral family, one deep teal accent, one radius scale, and self-hosted Geist / Geist Mono. Design rationale lives in `app/styles.css`.
- Build on shadcn/ui with Base UI primitives, the default primitive layer for new shadcn projects since July 2026. Components are vendored source owned by this repository, not a runtime dependency.
- Use beUI for motion, installed through the `@beui` shadcn registry namespace. Motion is applied only where it carries meaning (entrance sequencing, state-label swaps, theme change), and every animated component respects reduced motion.
- Keep Lucide as the single icon family, and use `next-themes` for the class-based dark mode strategy because the beUI theme toggle is built on it.

`README.md` documents how to add components and `docs/architecture.md` records where they live.

## Alternatives considered

**A styled component package (daisyUI, Flowbite, MUI)** — rejected because shadcn/ui was the chosen component system; a class-only or opinionated library would duplicate or fight the semantic token layer this app relies on.

**shadcn/ui on Radix** — rejected because Base UI is the default primitive layer for new shadcn projects, so Radix would add a second primitive stack with no compensating benefit.

**Hand-rolled motion components** — rejected because beUI already ships accessible, reduced-motion-aware primitives that follow the same vendored-source workflow as shadcn.

**Generated imagery for the hero** — rejected because no image-generation tool is available in this environment and div-built fake product screenshots would misrepresent the product. The hero shows a real composition of the app's own components, labelled as an example.
