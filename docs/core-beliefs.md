# Core beliefs

- Assessment inputs need evidence and explicit assumptions. Missing facts should produce follow-up questions, not invented monetary results.
- The model chooses questions and tools; deterministic TypeScript owns arithmetic. A capacity estimate or expected avoided loss is not guaranteed cash savings.
- Conversations are working context. Durable application records should remain useful independently of any particular agent session.
- Keep one repository and one Cloudflare application until a measured need justifies another service. Basic forms and explicit ownership are enough for this stage.
- Make incomplete behavior visible. Scripted responses, skill stubs, and unconnected tools must not be presented as a functioning AI assessment.

Authentication, billing, dashboards, complex state machines, multi-agent orchestration, RAG, vectors, ingestion, MCP/integrations, Redis, queues, and additional backends are outside this initialization. Revisit a boundary only with a concrete product need and record durable rationale when it would change future implementation choices.
